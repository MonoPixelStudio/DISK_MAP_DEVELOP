# DiskMap

맥북의 파일 용량을 시각적으로 살펴보고 정리하기 위한 개인용 macOS 앱입니다.

## 현재 상태

8개 마일스톤을 마친 개인용 버전 **1.0.0**입니다. 선택한 폴더를 시각적으로 분석하고, 검토·최종 확인을 거쳐 휴지통으로 이동합니다. 항목별 결과, 자동 재스캔, 디스크 여유 공간과 최근 위치·표시 설정 저장을 지원합니다.

바로 실행할 앱은 `dist/DiskMap.app`, 보관용 설치본은 `dist/DiskMap-1.0.0-arm64.zip`입니다. [빠른 시작](docs/QUICK_START.md)과 [릴리스 검증 기록](docs/RELEASE_VALIDATION.md)을 참고하세요.

- 왼쪽 스캔 위치, 가운데 계층별 원형 차트, 오른쪽 파일 목록과 상세 정보, 하단 정리 목록
- 실제 폴더 선택, 백그라운드 스캔, 진행 중 확인한 항목 수·용량·경로 표시
- 스캔 취소와 재실행. 스캔 중이거나 취소·실패하면 이전 완료 결과 유지
- 실제 파일과 폴더의 할당 용량, 파일의 논리 크기와 수정 시각 확인
- 숨김 파일 포함, 권한 오류와 제외 항목의 경로·사유 확인
- 샘플과 실제 결과 구분, 하위 폴더와 상위 폴더 이동
- 파일·폴더 이름 검색, 현재 폴더 또는 하위 폴더 포함 검색
- 용량·이름의 오름차순·내림차순 정렬, 파일·폴더 구분, 최소 할당 용량과 숨김 항목 필터
- 검색 결과의 포함 폴더로 이동, 실제 항목의 Finder 위치 표시와 전체 경로 복사
- 최대 2~4층의 선버스트 차트, 항목별 용량·비율·경로, 차트와 목록의 선택 연동
- 차트 폴더 더블 클릭으로 진입, 중앙·경로 버튼으로 복귀, 작은 항목 묶음에서 포함 폴더 목록 열기
- 정리 후보 담기·빼기·목록 비우기, 전체 경로·포함 파일 수·할당 용량 합계 검토
- 같은 항목과 상하위 폴더의 중복 집계 방지, 보호 경로·불완전한 스캔 항목의 후보 등록 제한
- 실행 직전 식별자·변경 상태·경로·폴더 내부 재검사, 확인창 후 macOS 휴지통 이동
- 항목별 성공·실패·건너뜀 결과, 남은 항목 중단과 정리 후 자동 재스캔
- 디스크 전체·여유 공간 조회와 새로고침, 최근 스캔 위치·표시 설정 저장

앱에서 **폴더 선택** 또는 `⌘O`를 누르고 분석할 폴더를 선택하세요. 완료하면 차트와 목록을 실제 결과로 바꿉니다. **샘플 보기** 또는 `⌘⇧H`로 샘플로 돌아갈 수 있습니다. 재실행 후에는 **최근 위치**에서 이전 폴더를 직접 선택해 다시 스캔합니다. 이전 스캔 결과와 정리 후보는 저장하지 않습니다.

## 원형 차트 탐색

1. 안쪽 고리는 현재 폴더 바로 아래 항목이고, 바깥 고리는 그 항목의 하위 폴더·파일입니다. 같은 가지는 같은 계열 색을 사용하며, 각 조각의 각도는 현재 폴더 전체에서 차지하는 할당 용량 비율입니다.
2. 조각에 마우스를 올리면 이름·용량·비율·경로를 확인합니다. 클릭하면 선택을 유지하고 오른쪽 목록의 해당 항목으로 스크롤합니다. 목록에서 선택해도 차트가 함께 강조됩니다.
3. **폴더 더블 클릭** 또는 **선택한 폴더 열기**로 안쪽에 진입합니다. **차트 중앙** 또는 상단 경로·뒤로 버튼으로 돌아갑니다. 최초 폴더에서는 중앙을 누르면 선택을 해제합니다. 파일 더블 클릭은 선택만 하며 파일을 실행하지 않습니다.
4. **최대 2층·3층·4층**으로 표시 깊이를 조절합니다. 실제 하위 계층이 더 짧으면 존재하는 층까지만 표시합니다.
5. 전체의 0.4%보다 작거나 표시 한도를 넘는 항목은 **기타 N개 항목**으로 묶습니다. 묶음을 선택하고 **포함 폴더 목록 보기**를 누르면 개별 항목을 확인할 수 있습니다. 묶음의 용량은 포함 항목의 정확한 합계입니다.

차트는 현재 폴더 전체 기준입니다. 차트에서 선택한 항목이 목록의 검색·필터 때문에 보이지 않으면, 해당 조건을 초기화하고 필요한 경우 하위 포함으로 바꾸며 안내를 표시합니다. 정렬은 유지합니다. 목록의 작은 항목은 해당 묶음을, 표시 깊이보다 안쪽 항목은 표시된 가장 가까운 상위 항목을 강조합니다.

0바이트와 용량 미확인 항목에는 면적을 만들지 않습니다. 이런 항목은 목록에서 확인하세요. 제외·접근 불가 항목이 있으면 확인된 용량만 그리며 부분 집계임을 표시합니다. 차트는 한 부모당 최대 32개, 한 층당 최대 128개, 전체 최대 512개 조각으로 제한하고 나머지는 묶습니다. 레이아웃 계산은 백그라운드에서 취소 가능하게 실행합니다.

## 파일 찾기

1. 오른쪽 검색창 또는 `⌘F`로 이름을 검색합니다. 대소문자와 한글의 유니코드 조합 차이를 구분하지 않으며, 파일 내용은 검색하지 않습니다.
2. **현재 폴더**는 바로 아래 항목만 표시합니다. **하위 포함**은 현재 폴더 안쪽의 모든 스캔 결과를 대상으로 합니다. 검색 결과에는 포함된 폴더 경로도 표시합니다.
3. 오른쪽 위 메뉴로 용량·이름 정렬을 바꿉니다. 이름은 숫자를 자연스럽게 정렬합니다(`item2` → `item10`). 용량을 알 수 없는 항목은 용량 정렬 시 항상 마지막에 표시합니다.
4. **필터**에서 파일만·폴더만, 1 MB·100 MB·1 GB 이상의 최소 할당 용량, 숨김 항목 표시 여부를 선택합니다. 숨김 폴더를 제외하면 그 안쪽 항목도 목록에서 제외합니다.
5. 항목을 선택하면 경로와 크기를 확인할 수 있습니다. **포함된 폴더로 이동**이나 폴더 오른쪽 화살표로 앱 안에서 탐색합니다. 폴더 이동 시 검색어는 지우고 나머지 조건은 유지합니다. **초기화**는 검색어와 필터를 초기화하며 정렬과 검색 범위는 유지합니다.
6. 실제 항목의 **Finder에서 보기**는 Finder에서 위치를 표시합니다. 파일을 기본 앱으로 실행하지 않습니다. **경로 복사**는 전체 경로를 클립보드에 복사합니다. 두 기능은 샘플에서 비활성화됩니다.

검색과 필터는 완료된 스캔 결과의 오른쪽 목록에만 적용되며, 가운데 차트의 용량은 현재 폴더 전체 기준입니다. 최소 용량도 확인한 할당 용량을 사용합니다. 스캔에서 제외한 폴더의 내부 파일은 검색할 수 없습니다. 파일이 스캔 후 사라지면 Finder 요청 대신 재스캔 안내를 표시합니다. 위치 표시에는 파일 삭제나 이동이 포함되지 않습니다.

## 정리 후보 관리

1. 차트나 목록에서 항목을 선택하고 상세 정보의 **정리 목록에 담기**를 누릅니다. 목록의 우클릭 메뉴에서도 담거나 뺄 수 있습니다. 담긴 항목과 그 하위 항목은 목록에 작은 트레이 표시가 생깁니다.
2. 하단에서 후보 수, 포함 파일 수와 할당 용량 합계를 확인합니다. **목록 검토** 또는 `⌘⇧L`로 전체 경로가 있는 검토 창을 엽니다.
3. 검토 창의 **앱에서 보기**로 해당 항목의 위치로 돌아갑니다. **빼기**, **목록 비우기**는 후보 목록만 변경하며 실제 파일은 그대로 있습니다.
4. 동일 항목은 한 번만 담습니다. 이미 담은 폴더의 하위 항목은 별도로 추가하지 않습니다. 하위 후보를 담은 뒤 상위 폴더를 담으면 하위 후보를 대체합니다. **이때 상위 폴더 안의 모든 파일이 후보에 포함되므로, 합계와 포함 파일 수를 다시 확인하세요.**
5. 후보는 최대 500개이며 현재 완료된 스캔 결과에만 속합니다. 폴더를 탐색하거나 검색 조건을 바꿔도 유지하지만, 새 스캔 완료·샘플 전환·앱 종료 시 초기화합니다. 스캔 취소·실패 시에는 이전 후보를 유지합니다. 스캔 중에는 담기를 제한합니다.

샘플에서도 후보 관리를 연습할 수 있고 **샘플 후보**로 표시합니다. 후보와 목록은 메모리에만 존재합니다. 샘플의 휴지통 이동은 비활성화됩니다. 표시되는 합계는 스캔 당시의 할당 용량이며 확보 가능한 공간의 보장값이 아닙니다.

후보 제한은 다음과 같습니다.

- 스캔한 최상위 폴더 전체와 스캔 범위 밖의 경로는 담을 수 없습니다. 경로의 구성과 부모·자식 관계도 검사합니다.
- 일반 파일과 집계가 완료된 폴더만 허용합니다. 링크·패키지·특수 파일, 제외·접근 불가·부분 집계 항목은 제한합니다. 폴더 내부에도 같은 검사를 적용하며, 부분 집계 폴더의 읽기 가능한 개별 파일은 담을 수 있습니다.
- `/System`, `/Library`, `/Applications`, `/bin`, `/sbin`, `/usr`, `/etc`, `/private`, `/var`, `/tmp`, `/dev`, `/cores`, `/opt`, `/Network`와 그 내부를 보호합니다. `/`, `/Users`, `/Volumes`, 현재 사용자의 홈 폴더 자체도 제한합니다.
- 현재 홈의 `Library`, `.Trash`, `.config`, `.local`, `Dropbox`, `OneDrive` 내부와, 경로에 `.ssh`, `.gnupg`, `.aws`, `.kube`, `.codex`가 포함된 항목을 보호합니다. 주요 패키지·`icloud` 확장자가 포함된 경로도 제한합니다. 보호 경로를 포함한 상위 폴더 전체는 담을 수 없습니다.

보호 목록은 보수적인 기본 규칙이며 모든 중요 파일이나 동기화 서비스를 판별하지는 않습니다. 후보를 담을 때는 저장된 스캔 결과를 검사하고, 실제 이동 직전에는 파일 시스템을 다시 검사합니다.

## 휴지통 이동과 결과

1. 후보를 담은 뒤 하단의 **휴지통으로 이동…** 또는 **목록 검토**를 엽니다. 각 항목의 전체 경로·파일 수·용량을 검토하고, 긴 경로는 마우스를 올려 확인합니다.
2. 검토 창의 **휴지통으로 이동…**를 누르면 최종 확인창을 표시합니다. **취소**하면 파일을 변경하지 않습니다. **휴지통으로 이동**을 확인한 경우에만 실제 이동합니다.
3. 실행 직전 스캔 범위와 보호 규칙, 상위 경로의 링크 여부·파일 식별자, 대상의 식별자·크기·수정/변경/생성 시각·권한·플래그 등을 재검사합니다. 폴더는 하위 이름 목록과 각 항목도 비교합니다. 사라졌거나 바뀐 항목, 새 내용이 생긴 폴더, 잠긴 항목과 확인 불가 항목은 건너뜁니다.
4. **남은 항목 중단**은 아직 시작하지 않은 항목을 건너뜁니다. 이미 시작한 macOS 이동 요청은 끝난 뒤 결과에 표시합니다. 준비·확인·이동 중에는 새 실행과 후보 변경, 다른 스캔·샘플 전환을 막습니다. 정상적인 앱 종료도 처리 중에는 제한합니다.
5. **최근 실행 결과**에서 성공·실패·건너뜀 사유와 macOS가 반환한 휴지통 경로를 확인합니다. 성공한 후보는 제거하고 선택한 스캔 루트 전체를 자동 재스캔해 차트·목록·하드 링크 집계를 갱신합니다. 변경되지 않고 여전히 허용되는 실패·건너뜀 후보만 새 결과에서 유지합니다. 바뀐 후보는 다시 확인해 담아야 합니다.
6. 재스캔을 취소하거나 실패하면 이전 화면과 결과를 유지합니다. 이동 전 목록이 남아 있는 동안 다음 정리는 제한하며, **다시 스캔**으로 최신 결과를 얻습니다. **휴지통에서 보기**는 이동한 항목을 Finder에서 표시합니다. 앱 종료 후 실행 결과는 저장하지 않습니다.

실제 이동은 [Apple의 `FileManager.trashItem` API](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))만 사용하며, 실패 시 영구 삭제로 전환하지 않습니다. 쓰기 가능한 **내장 로컬 디스크**만 정리 대상으로 허용합니다. 외장·네트워크 디스크 정리, 클라우드 정리와 앱에서 휴지통 비우기·자동 복원은 지원하지 않습니다. 복원이나 휴지통 비우기는 Finder에서 직접 수행하세요.

경로는 링크를 따라가지 않는 디렉터리 파일 디스크립터로 검사하고 native API 호출 경계에서 다시 확인합니다. 다만 macOS 휴지통 API는 경로를 받으므로 마지막 검사와 이동 사이의 외부 변경을 완전히 원자적으로 막을 수는 없습니다. 계속 수정되는 작업 폴더는 관련 작업을 멈추고 재스캔한 뒤 정리하세요. 하드 링크의 다른 이름을 먼저 이동해 상태가 바뀌면 이후 후보는 보수적으로 건너뛸 수 있습니다.

## 여유 공간과 저장되는 설정

- 사이드바의 **디스크 여유 공간**은 선택한 폴더가 속한 디스크의 전체 용량과 macOS가 보고한 여유 공간입니다. 폴더의 차트 합계와 별도로 표시하며 조회 시각도 표시합니다.
- 결과 화면의 **휴지통으로 옮긴 항목의 할당 용량**은 확보된 공간이 아닙니다. 휴지통·공유 블록·스냅샷과 다른 앱의 활동에 따라 여유 공간은 다르게 변할 수 있습니다. Finder에서 휴지통을 비운 뒤 **여유 공간 새로고침**으로 최신 수치를 조회하세요. 앱은 휴지통을 비우지 않습니다.
- 최근 완료된 스캔 위치를 중복 없이 최대 5개 저장합니다. 상단 **최근 위치**에서 직접 선택하면 다시 스캔하며, **최근 위치 목록 지우기**는 저장된 경로 목록만 지웁니다. 앱 실행 시 자동으로 개인 폴더를 스캔하지 않습니다.
- 차트 깊이, 목록 정렬, 검색 범위, 종류·최소 용량·숨김 표시 설정을 로컬에 저장합니다. 검색어·파일 트리·정리 후보·이동 결과는 저장하지 않습니다. 손상된 설정을 읽지 못하면 기본값과 안내를 표시합니다.
- 프로젝트의 `dist/DiskMap.app`을 실행하는 개발 환경에서는 설정을 프로젝트 내부 `.diskmap-state/preferences.json`에 저장합니다. 다른 위치에 설치한 앱은 자신의 `~/Library/Application Support/DiskMap/preferences.json`을 사용합니다. 개발 검증에서는 프로젝트 밖에 설정 파일을 만들지 않습니다. 설정 읽기·쓰기는 링크를 따라가지 않으며 임시 파일을 같은 설정 폴더에서 원자적으로 교체합니다.

권한 오류가 있으면 해당 폴더의 읽기·쓰기 권한과 시스템 설정의 **개인정보 보호 및 보안 → 파일 및 폴더**를 확인하세요. 앱은 권한을 바꾸거나 시스템 보호를 우회하지 않습니다. 읽지 못한 경로는 제외 사유와 함께 표시합니다.

## 스캔 정책과 용량 해석

- 일반 파일 내용을 열지 않고 파일 시스템 메타데이터로 집계합니다. 스캔 작업은 파일을 변경하지 않습니다.
- 할당 용량은 `st_blocks × 512`, 논리 크기는 `st_size`입니다. 폴더 자체의 메타데이터 공간은 합계에 포함하지 않습니다. 같은 스캔 안의 하드 링크는 할당 용량을 한 번만 더합니다.
- 심볼릭 링크와 Finder 별칭의 대상을 따라가지 않습니다. 다른 볼륨은 별도로 선택해야 하며, 폴더 깊이는 최대 128단계입니다.
- 앱·보관함 등 주요 패키지 확장자(`app`, `bundle`, `framework`, `photoslibrary`, `photolibrary`, `pkg`, `rtfd`, `playground`)는 내부 스캔에서 제외합니다.
- 알려진 클라우드 경로(`~/Library/CloudStorage`, `~/Library/Mobile Documents`, `~/Dropbox`, `~/OneDrive`), iCloud 항목과 인식 가능한 미다운로드 파일은 제외합니다. 자동 다운로드를 요청하지 않습니다. 임의 위치의 모든 동기화 서비스를 식별하는 것은 아닙니다.
- 접근 불가·제외 항목은 `알 수 없음`으로 표시합니다. 일부만 읽힌 폴더는 집계된 용량과 함께 불완전한 결과임을 표시합니다. 오류 목록은 전체 건수와 최대 100개의 상세 사례를 제공합니다.

APFS 복제 파일, 스냅샷, 압축과 공유 블록 때문에 집계한 할당 용량은 삭제 후 확보 가능한 공간과 다를 수 있습니다. 스캔 중 외부에서 파일이 바뀌면 시점별 메타데이터가 섞일 수 있으며, 원자적인 디스크 스냅샷은 만들지 않습니다.

스캔 시작·종료 사이에 폴더의 변경 상태가 달라지면 부분 집계로 표시하고 재스캔을 안내합니다. 모든 파일의 동시 변경을 감지하는 원자적 스냅샷은 아니므로 실제 이동 직전에는 대상과 하위 항목을 다시 검사합니다.

## 개발 환경

- macOS 14 이상을 대상으로 빌드합니다. 현재 검증 환경은 Apple Silicon과 macOS 26입니다.
- Swift 6 개발 도구와 macOS SDK가 필요합니다. Xcode Command Line Tools만으로 빌드할 수 있습니다.
- 외부 패키지, 서버, API 키는 필요하지 않습니다.

## 빌드와 실행

프로젝트 폴더에서 실행합니다.

```sh
./scripts/run-app.sh
```

릴리스 앱만 만들려면 아래 명령을 사용합니다.

```sh
./scripts/build-app.sh
```

결과는 `dist/DiskMap.app`입니다. Finder에서 열거나 Applications 폴더로 복사할 수 있습니다. 현재 빌드 스크립트는 개발용 ad hoc 서명을 사용하며, 다른 맥에 배포하기 위한 Developer ID 서명과 공증은 포함하지 않습니다.

아이콘·앱·ZIP·SHA-256 체크섬·안내문을 만들고 압축 사본을 검증하려면 다음을 실행합니다. 응용 프로그램 폴더에 자동 설치하지 않습니다.

```sh
./scripts/package-app.sh
./scripts/verify-package.sh
```

```sh
./scripts/test.sh
```

현재 Command Line Tools에는 Swift Testing 모듈이 없어, 외부 테스트 의존성 없이 실행되는 `DiskMapChecks` 검증 프로그램을 사용합니다. 실패하면 0이 아닌 종료 코드를 반환합니다.

실제 5만 개 파일을 만들어 스캔·검색·차트·탐색·취소의 시간과 CPU, 프로세스 최대 메모리를 측정하려면 `./scripts/benchmark.sh`를 실행합니다. 파일 생성 시간은 별도이며 생성한 파일은 실행 후 정리합니다. 결과는 JSON으로 출력합니다.

검증용 파일은 프로젝트 내부 `.diskmap-test-fixtures/`에만 생성하고, 해당 실행에서 만든 고유 폴더만 정리합니다. 실제 휴지통 자동 검증도 직접 만든 고유 이름의 파일·폴더만 이동하고, 반환 경로와 식별자를 확인해 해당 파일만 복원한 뒤 정리합니다. 기존 휴지통 항목은 열거나 비우지 않습니다. 사용자의 다른 기존 파일은 테스트 대상으로 수정·이동·삭제하지 않습니다. 이후 개발에도 적용할 작업 범위는 `AGENTS.md`에 기록되어 있습니다.

## 프로젝트 구조

| 경로 | 역할 |
| --- | --- |
| `Sources/DiskMap` | SwiftUI 앱, 화면, 탐색 상태, 폴더 선택창 |
| `Sources/DiskMapCore` | 스캔·검색·차트, 파일 식별자·후보 보호·실행 전 검사·휴지통 배치 결과, 여유 공간·설정 저장 |
| `Tests/DiskMapCoreTests` | 실제 스캔·검색·차트·후보·휴지통 왕복·변경 감지·부분 실패·설정·용량 등 39개 검증 묶음과 성능 측정 |
| `Support/Info.plist` | 앱 번들 설정 |
| `scripts` | 빌드·아이콘·패키징·압축 사본 검증·성능 측정·실행 스크립트 |
| `docs/MILESTONES.md` | 개발 단계와 검증 기록 |
| `docs/QUICK_START.md` | 설치와 분석·정리 사용 안내 |
| `docs/RELEASE_VALIDATION.md` | 환경·성능·릴리스 검증 결과와 미검증 범위 |

스캔은 `DiskScanning`과 `LocalDiskScanner`, 정리 실행은 `TrashManaging`과 `LocalTrashManager`로 화면에서 분리합니다. 스캔 이벤트는 `AsyncThrowingStream`으로 전달하며 디렉터리 파일 디스크립터를 기준으로 순회합니다. `CleanupQueue`와 `CleanupPolicy`는 한 스캔 결과의 후보만 관리합니다. 실제 요청에는 `FileFingerprint`와 스캔 스냅샷을 포함하고, `TrashValidation`과 직렬 actor의 검사 후 native API를 호출합니다. `TrashBatch`는 항목별 결과와 중단을 처리합니다. `VolumeSpace`와 `SettingsStore`는 공간 조회와 자체 설정 저장을 담당합니다.

`FileSnapshotIndex`는 큰 결과의 탐색과 경로 조회를 위해 한 번 구성합니다. 파일마다 전체 노드를 복제하는 대신 부모 폴더와 자식 위치를 기록합니다. 색인 생성과 정리 후 후보 비교는 백그라운드에서 처리하며, 색인은 파일 이동의 허가에 사용하지 않습니다.
