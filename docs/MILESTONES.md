- 실제 앱: 프로젝트 테스트 파일 2개·3.1 MB의 전체 경로 검토와 확인창 확인. 확인창 취소 후 3개 테스트 파일이 그대로인 것 확인
- 실제 앱: 후보 하나만 스캔 후 수정한 뒤 실행하여 **이동 1개·건너뜀 1개·실패 0개**, 수정한 항목의 재스캔 안내와 native 휴지통 경로 확인
- 자동 재스캔 후 이동한 항목이 목록에서 사라지고 바뀐 파일의 1.2 MB 크기가 반영되며, 변경된 실패 후보가 다시 담기지 않는 것 확인
- 결과 화면의 이동 용량 2.1 MB와 디스크 여유 공간을 별도 표시, 새로고침 시 새 조회 시각·공간 값 반영 확인
- 차트 최대 4층·이름 오름차순으로 바꾸고 앱을 종료·재실행하여 설정 복원 확인. 최근 위치에서 같은 테스트 폴더를 다시 선택해 스캔하는 것 확인
- 최종 빌드에서 확인창을 연 채 `⌘Q`를 눌러 앱이 종료되지 않는 것 확인. 확인을 취소한 뒤 추가 이동 없이 정상 종료 확인

이번 작업에서는 프로젝트 밖의 기존 사용자 파일을 수정·이동·삭제하지 않았고, 다른 앱 UI를 열거나 조작하지 않았습니다. Finder 위치 표시 API는 연결했지만 Finder 창 자체의 UI 검증과 기존 휴지통 비우기는 수행하지 않았습니다. UI 테스트에서 이동한 **`이동할파일.bin` 1개(2 MiB)**는 `/Users/byeongju/.Trash/이동할파일.bin`에 남겨 두었습니다. 반환 경로의 inode가 직접 만든 테스트 파일과 일치하는 것을 확인했지만 macOS가 개발 도구의 읽기·복원 요청을 거부했습니다. 권한을 확대하거나 휴지통을 비우지 않았으며, 프로젝트에 남은 이번 테스트 파일과 개발 검증용 설정만 정리했습니다.

휴지통 API는 파일 디스크립터가 아닌 경로를 받으므로 마지막 검사와 native 호출 사이의 외부 변경을 완전히 원자적으로 차단하는 보장은 하지 않습니다. 파일을 계속 쓰는 작업을 중지하고 재스캔한 뒤 정리하는 개인용 사용 범위입니다. 외장·네트워크·클라우드 정리, 앱에서 자동 복원·영구 삭제·휴지통 비우기는 제외합니다. macOS 14·15 및 Intel 맥, 실제 VoiceOver 탐색, Finder에서 사용자가 휴지통을 비운 직후의 통합 확인은 아직 검증하지 않았습니다.

다음 8단계는 성능·장시간 사용·추가 변경 경쟁 검증과 설치본 마무리입니다. 다른 맥에 배포하기 위한 Developer ID 서명·공증은 현재 개발용 빌드에 포함되지 않습니다.

## 마일스톤 8 구현과 검증 기록

2026년 10월 9일, Apple Silicon과 macOS 26.6.2에서 개인용 버전 **1.0.0(빌드 8)**을 완성했습니다. 8개 개발 마일스톤을 모두 마쳤습니다. [빠른 시작](QUICK_START.md)과 [상세 검증·성능·미검증 범위](RELEASE_VALIDATION.md)를 별도 문서로 제공합니다.

스캔 폴더의 시작·종료 변경 상태를 비교합니다. 내용 변화나 확인 실패를 감지하면 부분 집계로 표시하고 재스캔 사유를 기록합니다. 실행 전의 기존 파일·폴더 검사는 유지합니다. 탐색용 `FileSnapshotIndex`는 백그라운드에서 한 번 만들고 부모 폴더·자식 위치를 기록합니다. 화면 갱신 시 현재 폴더와 선택·경로를 찾기 위해 전체 트리를 반복 순회하지 않으며, 정리 후 남은 후보의 큰 트리 비교도 백그라운드에서 수행합니다.

5만 개 4 KiB 파일의 실제 릴리스 스캔은 8.323초, 색인 생성 0.308초, 검색 0.074초, 차트 계산 0.0016초였습니다. 같은 항목 500회 조회는 기존 3.516초에서 색인 방식 0.0036초로 줄었습니다. 벤치마크 전체 프로세스 최대 RSS는 534 MiB입니다. 수치는 이 맥에서의 단일 측정이며 다른 저장장치·경로·작업에 대한 보장값은 아닙니다.

압축 사본을 프로젝트 내부 별도 위치에서 실행해 100,102개 파일의 스캔·취소·재실행과 검색·보호 경로 제한·후보 검토·확인 취소·목록 비우기·설정 복원을 확인했습니다. 전체 UI 스캔은 33.7초였고 파일 내용·이름·크기와 빈 파일의 권한이 유지됐습니다. 실제 이동은 자동 검증의 직접 만든 고유 파일·폴더만 사용하고 확인 후 복원했습니다.

`package-app.sh`는 릴리스 앱과 아이콘·ZIP·SHA-256·사용 안내를 만들고, `verify-package.sh`는 고유 프로젝트 테스트 폴더에서 압축 사본의 바이너리·버전·서명·아이콘·최소 OS를 확인합니다. `benchmark.sh`로 같은 5만 파일 측정을 재현할 수 있습니다. 실제 `/Applications`에는 설치하지 않았으며 현재 설치본은 arm64·ad hoc 서명입니다. macOS 14·15 실제 기기, Intel, 수시간 사용, 실제 VoiceOver와 Developer ID 서명·공증은 이번 개인용 완료 범위에 포함하지 않습니다.

프로젝트 밖의 기존 사용자 파일은 수정·이동·삭제하지 않았고 관련 없는 앱이나 브라우저 탭을 조작하지 않았습니다. 이전 단계의 휴지통 테스트 파일 한 개도 이번 실행에서는 그대로 두었습니다. 이번 검증 데이터·사본·설정만 생성한 고유 프로젝트 테스트 폴더에서 정리했습니다.
