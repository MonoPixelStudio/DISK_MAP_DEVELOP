# DiskMap 1.0.0 릴리스 검증

2026년 10월 9일. 개인용 Apple Silicon 릴리스, 빌드 8.

## 환경

- 실제 맥: Mac16,1, arm64, 메모리 16 GiB, 논리 CPU 10개
- macOS 26.6.2 (25G83), Swift 6.2.4, SDK 26.2, 최소 배포 대상 macOS 14.0
- 외부 패키지 의존성 없음. ad hoc 서명이며 Developer ID 서명·공증은 없음
- 테스트 데이터는 프로젝트 `.diskmap-test-fixtures/`의 실행별 고유 폴더만 사용

## 자동 검증

릴리스 `DiskMapChecks`의 **39개 검증 묶음 통과**. 이전 34개에 다음 5개를 더했습니다.

| 추가 검증 | 확인한 결과 |
| --- | --- |
| 긴 한글 경로 | 9단계 폴더와 600바이트를 넘는 경로, 유니코드 조합 차이가 있는 검색, 휴지통 실행 전 검사 후 내용·시각·권한·식별자 보존 |
| 스캔 중 변경 | 5천 개 파일을 스캔하는 동안 새 파일 추가와 기존 파일 변경, 부분 집계·변경 사유, 이전 후보의 실행 거부, 다음 스캔에서 새 크기 반영 |
| 많은 권한 오류 | 직접 만든 폴더 150개의 읽기 권한 거부, 전체 건수 유지·상세 사례 최대 100개, 테스트 권한 복구 후 정상 스캔, 보호용 `.ssh` 파일 보존 |
| 반복 실행 | 취소·재스캔·검색·차트 30회 반복, 이후 파일 수·내용 유지, 열린 디렉터리 파일 디스크립터 누수 없음 |
| 탐색 색인 | 원래 트리와 같은 항목·경로, 하위 경계·없는 항목, 중복 식별자 거부, 색인 생성 취소 |

기존 검증에는 링크·순환 링크·범위 밖 경로·클라우드 제외·패키지·깊이 제한, 하드 링크·희소 파일, 후보 중복·보호 경로, 실행 직전 교체·이름 변경·새 하위 항목 검사, 부분 성공·실패·중단, 설정 손상·링크 쓰기 거부가 포함됩니다. 실제 macOS 휴지통 API도 이번 실행에서 만든 고유 파일과 폴더만 이동하고, 반환 경로와 inode·장치를 확인해 해당 항목만 복원했습니다. 선택하지 않은 테스트 파일은 내용과 메타데이터가 유지됐습니다.

원본 로그: `dist/validation/release-checks.txt`, `dist/validation/package-checks.txt`.

## 성능

릴리스 실행 파일에서 한글 폴더 100개와 **4 KiB 파일 50,000개(204.8 MB)**를 직접 생성했습니다. 생성 시간은 스캔 측정에서 제외했습니다. 아래 값은 이 맥에서 한 번 측정한 값이며 디스크 캐시·다른 작업·경로 길이에 따라 달라집니다.

| 작업 | 경과 시간 | 프로세스 CPU 시간 |
| --- | ---: | ---: |
| 실제 스캔 | 8.323초 | 7.648초 |
| 탐색 색인 생성 | 0.308초 | 0.410초 |
| 색인으로 항목 500회 조회 | 0.0036초 | 0.0036초 |
| 하위 이름 검색·정렬(1,100개 결과) | 0.074초 | 0.073초 |
| 4층 차트 계산(63개 조각) | 0.0016초 | 0.0016초 |
| 첫 진행 이벤트에서 스캔 취소 | 0.00063초 | 0.00069초 |

이전 트리 순회 방식의 같은 500회 조회는 **3.516초**였습니다. 현재 폴더·선택 항목·경로 조회를 색인으로 바꾸고, 목록의 후보 표시도 매번 전체 트리를 찾지 않도록 변경했습니다. 재스캔 후 큰 폴더의 후보 비교도 메인 스레드 밖에서 수행합니다.

벤치마크 프로세스 최대 RSS는 **534 MiB**입니다. 파일 생성과 스캔·색인·검색 등 전체 프로세스의 최대값이며 앱 창만의 메모리 사용량은 아닙니다. 자동 취소 수치는 UI 클릭 지연이 아닌 스트림 소비자 취소 측정입니다.

원본: `dist/validation/performance-baseline.json`, `dist/validation/performance-final.json`. 재현: `./scripts/benchmark.sh`.

## 설치본

`dist/DiskMap.app`과 `dist/DiskMap-1.0.0-arm64.zip`, ZIP의 `.sha256`, `dist/QUICK_START.md`를 생성했습니다. ZIP을 프로젝트 테스트 폴더에 풀어 앱 서명·실행 권한·버전·원본 바이너리 일치·아이콘 해상도·최소 OS를 확인했습니다. 빌드·패키징 스크립트는 출력 경로의 심볼릭 링크를 거부합니다.

실제 응용 프로그램 폴더 설치는 사용자의 파일 작업 범위에 따라 수행하지 않습니다. 압축에서 꺼낸 앱을 프로젝트 내부의 별도 위치에서 실행하는 방식으로 확인하며, 이 사본의 설정도 고유 테스트 폴더 안에 저장합니다.

## 실제 앱 확인

- ZIP에서 꺼낸 사본을 별도 프로젝트 테스트 위치에서 실행. 버전 1.0.0, 샘플의 실제 이동 비활성 확인
- **100,102개 파일**과 101개 하위 폴더로 검증. 100,000개 빈 파일, 그룹마다 64 KiB 파일 100개, 2 MiB 파일과 보호 경로용 4 KiB 파일 사용
- 약 15,000개 확인 중 취소해 샘플 화면 유지와 다시 스캔 활성 확인. 재실행 후 **100,203개 항목·33.7초·파일 100,102개·8.7 MB** 완료 결과 확인
- 한글 이름 검색·하위 포함 검색·파일 선택과 차트 연동, 포함된 폴더로 이동과 경로 표시 확인
- 2 MiB 파일 후보 담기·전체 경로 검토·최종 확인창 **취소**·후보 목록 비우기 확인. UI 검증에서는 실제 이동을 실행하지 않음
- 직접 만든 `.ssh/선택 금지.txt`의 정리 제한 사유와 후보 버튼 없음 확인
- 종료 후 테스트 파일 100,102개의 이름·크기·내용과 빈 파일의 권한 보존 확인
- 재실행 시 샘플 시작, 검색어·후보 초기화, 하위 포함 조건과 최근 위치 복원, 자동 스캔 없음 확인
- 프로세스 CPU·RSS를 약 0.2초 간격으로 300회 측정. 관측 최대 **703 MiB RSS·CPU 163.6%**(100%는 논리 CPU 한 개 수준). 취소와 재실행을 포함한 측정이며 전체 실행의 엄밀한 최대값은 아님. 완료 후 관측은 RSS 약 87 MiB·CPU 0%
- 정상 종료 후 이번 고유 테스트 폴더와 사본·테스트 설정만 정리. 프로젝트의 기본 설정 파일을 만들거나 사용자 설치 위치를 변경하지 않음

원본 프로세스 측정: `dist/validation/ui-process-samples.json`. 대량 결과의 전체 접근성 트리 조회에서 자동화 도구가 시간 제한에 도달한 사례가 있었습니다. 화면 캡처와 검색으로 좁힌 목록의 키보드·선택·검토 동작은 확인했으며, 실제 VoiceOver 탐색은 별도 검증 대상입니다.

## 검증 범위의 한계

- macOS 14·15 실제 기기, Intel 맥, 수시간 연속 사용과 수백만 개 파일, 실제 VoiceOver 음성 탐색은 검증하지 않았습니다.
- Finder 앱 UI와 사용자가 휴지통을 비운 직후의 통합 동작, 외장·네트워크·클라우드 정리는 검증 범위에서 제외했습니다.
- 스캔은 원자적 파일 시스템 스냅샷이 아닙니다. 폴더 변경을 감지해도 모든 파일의 동시 변경을 감지하는 보장은 없습니다. 휴지통 API의 마지막 검사와 경로 기반 호출 사이의 외부 변경도 완전히 원자적으로 막을 수 없습니다.
- 시스템 파일 접근 권한이나 전체 디스크 접근 권한, Gatekeeper 설정을 변경하지 않았습니다. 앱은 접근 불가를 표시하며 영구 삭제로 대체하지 않습니다.
- 이전 6~7단계에서 직접 만든 `이동할파일.bin` 2 MiB 한 개가 사용자 휴지통에 남아 있습니다. 그 당시 개발 도구의 복원 요청이 macOS에 의해 거부됐으며, 이번 작업에서는 해당 파일이나 기존 휴지통을 조작하지 않았습니다.
